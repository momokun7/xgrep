# Review guide

Read by human reviewers and by AI review (`/code-review`, `/security-review`). Keep it short; move comments you find yourself repeating into it.

## What failure looks like here

In order of severity:

1. **Missed matches.** Any change that can drop a real match is a bug, even if it is rare: trigram/regex candidate extraction (`trigram_query.rs`, `candidates.rs`), index masks and folding (`index/`), path filters and `--max-count` pushdown (`search.rs`), the freshness overlay and watcher (`index/updater.rs`, `watch.rs`). Ask for a proptest or a grep cross-check, not reasoning alone.
2. **Stale or corrupt index.** Edits that are not picked up (mtime races, new dirs, ignore-rule changes), on-disk format changes without a version bump, non-atomic writes, lock races.
3. **Agent-facing output that misleads or explodes.** MCP/`--format llm` output past `max_tokens`, results marked "already shown" that were never shown, wrong line numbers, hints that are false.
4. **Unsafe file access.** `read_file` or any path input escaping the root, following symlinks out, or spawning processes from the searched tree.
5. **Performance regressions** on the hot path (candidate lookup, scan, output) without numbers.

## How to report

- Every finding needs evidence: `file:line` plus a concrete input or command that fails. No guesses.
- Tag each finding **Important**, **Nit**, or **Pre-existing** (bug not introduced by this PR).
- At most 3 nits per review. Skip style that `cargo fmt` / clippy already enforce.
- Start the summary with a count ("2 important, 1 nit"). If there is nothing to fix, say so plainly.
- Do not repeat a finding that was resolved with a reason. Flag the bug class once, listing every instance.

## Skip

- `CHANGELOG.md`, `rust/CHANGELOG.md`, `python/CHANGELOG.md` (generated by release-please)
- `**/Cargo.lock`, `npm/package-lock.json`
- `bench/`, `benchmarks/` scripts and results unless the PR is about them

## Risk tiers

Set by what the change touches, not by who wrote it.

| Tier | Touches | Before merge |
|---|---|---|
| Low | docs, comments, tests only, bench scripts | CI green |
| Medium | search, output, CLI, MCP tools, syntax features | CI green, `/code-review` run, all threads resolved |
| High | index format/builder/reader, freshness/watcher, `read_file` and path handling, `.github/workflows/`, release config, packaging (`npm/`, `python/`, `Cargo.toml`) | Medium + `/code-review high` + `/security-review`, a regression test for each fix, and the maintainer reads the evidence (test output, commands) |

An AI review posts findings; it never counts as an approval.
